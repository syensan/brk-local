What is BRK?

BRK (Breakthrough Container) is a file format and Python CLI tool that compresses time-series sensor data into a contract-bound semantic specification. Instead of bit-exact compression, BRK preserves statistical properties, trends, daily cycles, and anomalies — enabling approximate reconstruction within defined tolerances.

The reconstructed data is NOT the original data. It is a semantic-equivalent approximation that satisfies the reconstruction contract. This approach is designed for agricultural and IoT sensor data where statistical fidelity matters more than individual data points.

Streaming Processing

Two-pass streaming handles 1GB+ CSV files without loading into memory. Welford's algorithm for numerical stability.

Anomaly Detection

Z-score anomaly detection with configurable threshold. Top anomalies preserved as sparse residuals for injection during reconstruction.

Contract-Bound

Explicit reconstruction contract with tolerances. Semantic checksum (SHA-256) verifies specification integrity.

100% Local

No cloud, no serverless, no external AI APIs. Runs entirely on your local machine or on-premises server.

Quick Start

Install

cd brk-local
pip install -e .

Compress

brk compress-sensor examples/sample_sensor.csv output.brk

Output: Output size, budget status, and explicit "Lossless: false" notification.

Inspect

brk inspect output.brk

Verify

brk verify output.brk

Reconstruct

brk decompress-sensor output.brk reconstructed.csv --step-minutes 60

The reconstructed CSV is a semantic-equivalent approximation, NOT the original data.

How Reconstruction Works

The trend_daily_cycle_anomaly_injection decoder generates approximate values:

  1. Base trend: first + slope_per_second × elapsed_seconds
  2. Daily cycle: hourly_mean[current_hour] - mean (if available)
  3. Anomaly injection: Recorded anomalies replace calculated values at their timestamps

This produces a time series that preserves statistical properties and detected anomalies, but is NOT bit-exact to the original.

When to Use / Not Use BRK

✅ Suitable for

  • Agricultural sensor data with regular intervals and daily patterns
  • IoT environmental monitoring with periodic readings
  • Time-series data where statistical properties matter more than individual points
  • Scenarios needing dramatic size reduction with acceptable approximation

❌ NOT suitable for

  • Data requiring bit-exact preservation (financial transactions, medical records)
  • Legal evidence or regulatory compliance data
  • Cryptographic keys, secrets, or authentication tokens
  • Any application where data loss is unacceptable
